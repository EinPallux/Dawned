# Dawned — Tech Stack (choices & rationale)

> Modern, boring-where-it-counts, chosen for: browser 3D action combat, a 1-core/4 GB VPS,
> 5–20 concurrent players, and long-term editability by one owner. Versions pinned at Phase 0;
> "latest stable at implementation time" applies within the majors below.

## Summary Table

| Layer                             | Choice                                                                                                                                                                 | Why (and why not the alternative)                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Language                          | **TypeScript 5.x, strict** everywhere (client, server, shared, tools, admin)                                                                                           | One language across the whole project; shared game-logic packages (formulas, protocol) are the anti-desync strategy. No `any` policy.                                                                                                                                                                                                                                         |
| Runtime (server)                  | **Node.js 22 LTS**                                                                                                                                                     | LTS through the project's life; worker_threads unused (1 core — single process discipline instead). Bun/Deno rejected: ecosystem risk for a long-lived personal project.                                                                                                                                                                                                      |
| Monorepo                          | **pnpm workspaces** (`packages/client`, `packages/server`, `packages/shared`, `tools/`)                                                                                | Fast, disk-cheap, first-class workspace protocol. Dawned-Admin (separate repo) consumes `@dawned/shared` via pnpm git dependency (`github:EinPallux/Dawned#path:packages/shared`).                                                                                                                                                                                            |
| 3D engine                         | **Three.js** (WebGL2)                                                                                                                                                  | Most mature/documented WebGL scene graph, gigantic ecosystem (GLTFLoader, meshopt, three-mesh-bvh). Babylon rejected (heavier, less low-poly-community momentum); custom engine rejected (no shortcuts ≠ reinventing renderers). WebGPU: not for 0.1.0 (coverage), renderer abstraction keeps the door open.                                                                  |
| Client build                      | **Vite 7**                                                                                                                                                             | Instant dev loop, asset handling, code-splitting for screens; vanilla TS game core + React UI both served by one dev server.                                                                                                                                                                                                                                                  |
| Game UI                           | **React 19 + Zustand** (DOM overlay above canvas)                                                                                                                      | Crisp text/a11y/iteration speed for ~20 screens; game-loop data flows through refs/stores with per-frame writes outside React render (no re-render-per-frame trap). In-canvas UI rejected (text quality, dev speed); imgui-style rejected (styling goals).                                                                                                                    |
| Client-side state/netcode         | Custom thin ECS-ish systems (plain TS classes + typed component maps)                                                                                                  | The game is systems-driven (prediction, interp, VFX pools); a full ECS framework (bitecs/miniplex) adds concepts without payoff at this entity scale (≤ ~600 visible).                                                                                                                                                                                                        |
| Networking                        | **WebSocket (`ws` 8.x)** + custom binary protocol (shared encoder/decoder package)                                                                                     | At ≤20 CCU, `ws` on Node is far below capacity; pure-JS keeps deploys trivial. uWebSockets.js noted as a swap-in if CCU targets ever 10×. WebTransport/WebRTC-DC rejected for 0.1.0 (complexity vs. benefit at our RTTs; TCP HoL acceptable at 20 Hz with small packets). Protocol: hand-rolled DataView writers (hot path) + JSON envelopes (cold path) — see NETWORKING.md. |
| HTTP/REST (auth, content bundles) | **Fastify 5** on the same Node process                                                                                                                                 | One process on one core; Fastify's schema validation pairs with zod (via fastify-type-provider-zod). Express rejected (slower, older ergonomics).                                                                                                                                                                                                                             |
| Database                          | **PostgreSQL 16**                                                                                                                                                      | Two writer apps (game server + admin server) → a real multi-client DB, transactions for inventory/trades, JSONB for flexible content rows, `LISTEN/NOTIFY` for content-publish signals, pg_dump backups. SQLite rejected only because of the two-process admin architecture (it was otherwise sufficient). RAM budget ~300 MB tuned (see DEPLOYMENT.md).                      |
| ORM / migrations                  | **Drizzle ORM + drizzle-kit**                                                                                                                                          | TypeScript-first schema as code (schema lives in `@dawned/shared` → both repos see identical types), SQL-transparent, light runtime. Prisma rejected (engine weight on a 1-core box, codegen friction).                                                                                                                                                                       |
| Validation                        | **zod 4** at every boundary (REST bodies, admin writes, content rows, protocol JSON envelopes)                                                                         | One validation vocabulary shared with editors: the Admin panel derives forms from the same schemas.                                                                                                                                                                                                                                                                           |
| Auth                              | **argon2id** (`@node-rs/argon2`) + opaque session tokens (DB-backed, httpOnly cookie for admin, bearer for game)                                                       | Spec: account name + password. No email/OAuth. Details in SECURITY.md.                                                                                                                                                                                                                                                                                                        |
| Asset pipeline                    | **gltf-transform** + **meshoptimizer** (gltfpack), sharp (thumbnails/atlases), custom manifest generator                                                               | FBX→GLB conversion offline (Blender headless batch for the FBX-only packs), meshopt-compressed GLBs served with long-cache hashes. See ASSET_PIPELINE.md.                                                                                                                                                                                                                     |
| Physics/collision                 | Custom: heightfield sampling + static collider capsule/AABB tests + three-mesh-bvh for editor picking                                                                  | Full physics engines (Rapier etc.) rejected: an MMO server needs deterministic cheap checks, not rigid-body sim. Characters are kinematic capsules.                                                                                                                                                                                                                           |
| Pathfinding                       | Baked walkability grid (map publish) + A* (server), steering behaviors                                                                                                 | recast/navmesh rejected for 0.1.0: heightmap+props world with grid bake is simpler, editable, and debuggable in the admin editor (grid overlay).                                                                                                                                                                                                                              |
| Testing                           | **Vitest** (shared/server logic: formulas, protocol codec, loot rolls, XP), Playwright smoke (login→spawn→move loop vs dev server), manual playtest matrices per phase | Test what breaks silently (math/codec/persistence); don't chase UI pixel tests.                                                                                                                                                                                                                                                                                               |
| Lint/format                       | ESLint 9 (typescript-eslint strict) + Prettier                                                                                                                         | Enforced in CI script + pre-commit (lefthook).                                                                                                                                                                                                                                                                                                                                |
| Logging/metrics                   | **pino** (server, JSON logs → journald), tiny in-process metrics ring (tick ms, entities, net io) exposed on admin API `/metrics.json`                                 | Full Prometheus/Grafana rejected on 4 GB; Dawned-Admin renders the metrics ring. Optional Uptime Kuma noted in DEPLOYMENT.md.                                                                                                                                                                                                                                                 |
| Web server / TLS                  | **Caddy 2**                                                                                                                                                            | Automatic Let's Encrypt for play.pathlands.cc, reverse proxy (WS + HTTP), static asset serving with precompressed br/gzip, one readable Caddyfile. nginx rejected: more config for zero gain here.                                                                                                                                                                            |
| Process mgmt                      | **systemd** units (`dawned-game`, `dawned-admin`)                                                                                                                      | Native, restart policies, journald logs, no PM2 daemon layer.                                                                                                                                                                                                                                                                                                                 |
| CI                                | Repo scripts (`pnpm check` = typecheck+lint+test) — run locally & via GitHub Actions (free tier) on push                                                               | Deploys stay manual-triggered (`UPDATE.sh`) per "simple deployment" requirement.                                                                                                                                                                                                                                                                                              |

## Version Pins (Phase 0 lockfile targets)

Node 22.x · TS 5.6+ · three r17x · Vite 7 · React 19 · Fastify 5 · ws 8 · Drizzle latest ·
PG 16 (apt) · Caddy 2.8+ · pnpm 9. All exact versions land in the lockfile at Phase 0 and are
recorded in CHANGELOG.

## Browser Support Contract

Chromium 120+ / Firefox 120+ / Safari 17+ on desktop. WebGL2 required (hard gate screen with a
friendly message). 1080p and 1440p are first-class; 1366×768 must be _usable_ (UI scale 90%);
mobile explicitly unsupported in 0.1.0 (blocking screen with a wink).

## Performance Budgets (enforced per phase, tracked in CHANGELOG)

| Surface      | Budget                                                                                                        |
| ------------ | ------------------------------------------------------------------------------------------------------------- |
| Client       | 60 FPS @1080p mid-GPU: ≤300 draw calls, ≤500k tris in view, ≤250 MB GPU textures, JS main-thread frame ≤10 ms |
| Initial load | ≤8 MB critical path (login→char select), world streams after                                                  |
| Server       | tick p95 ≤25 ms @ 20 Hz with 20 players + 150 active AI; RSS ≤700 MB                                          |
| VPS total    | steady-state RAM ≤2.6 GB (game+admin+PG+Caddy+OS), leaving 1.4 GB headroom                                    |
| Network      | ≤12 kB/s down per client steady-state, ≤30 kB/s burst combat                                                  |
